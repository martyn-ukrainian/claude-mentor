# 09 — Transformers: механіка self-attention

## Що це

**Self-attention** — механізм, що дозволяє кожному елементу послідовності (токену) напряму "подивитись" на **всі** інші елементи одразу і визначити, наскільки кожен з них релевантний, без покрокового проходу (RNN) чи фіксованого локального вікна (CNN). Це фундамент архітектури **Transformer**.

## Для чого

RNN (Урок 08) несе інформацію через hidden state крок за кроком — щоб токен №50 "побачив" токен №1, інформація має пройти через 49 проміжних кроків (звідси vanishing gradient на довгих послідовностях, і послідовна, неparalельна обробка — повільно на GPU). Attention вирішує обидві проблеми одразу: прямий зв'язок між будь-якими двома токенами незалежно від відстані, і обчислення для **всіх** токенів одночасно, не по черзі.

## Розбір

### Query / Key / Value

Кожен токен перетворюється **трьома незалежними** навченими проекціями (`nn.Linear`) на три вектори:

- **Query** — "що я шукаю"
- **Key** — "за чим мене можна знайти"
- **Value** — "що я реально несу", якщо мене оберуть

Важливо: `Q`, `K`, `V` рахуються **паралельно й незалежно** з того самого входу `x` — жоден не чекає на інший. Залежність з'являється тільки на наступному кроці, коли `Q` і `K` використовуються **разом**.

### Крок за кроком, на конкретному прикладі

2 токени, вектори розміром 2:

```
Q1=[1,0]  K1=[1,0]  V1=[10,0]
Q2=[0,1]  K2=[0,1]  V2=[0,20]
```

**1. Релевантність (`scores`)** — dot product `Query` одного токена з `Key` іншого, **для кожної пари одразу**:

```
        K1   K2
Q1      1    0
Q2      0    1
```

`Q1·K1 = 1*1+0*0 = 1` (токен 1 "схожий" сам на себе — очікувано, `Q1` і `K1` вказують в один бік). `Q1·K2 = 1*0+0*1 = 0` (перпендикулярні вектори — нуль релевантності).

**2. Softmax** (по кожному рядку окремо) перетворює "сирі" оцінки на ваги, що сумуються в 1: `[1, 0] → [0.73, 0.27]`. Softmax ніколи не дає рівно `0`/`1` — навмисно, щоб градієнт міг текти через **усі** токени під час навчання, навіть менш релевантні (та сама ідея, що `predict_proba` замість жорсткого класу — м'яка оцінка дає більше сигналу для навчання).

**3. Зважена сума `Value`** — вихід токена 1:

```
output_1 = 0.73*V1 + 0.27*V2 = 0.73*[10,0] + 0.27*[0,20] = [7.3, 5.4]
```

Вихід — **суміш**, здебільшого власне значення токена (`V1`), з домішкою релевантних сусідів, **точно пропорційною вазі**.

Формула цілком: `Attention(Q,K,V) = softmax(QKᵀ/√d) V` (ділення на `√d` — стабілізує масштаб перед softmax, аналогічно ролі BatchNorm з Уроку 07, тільки тут це аналітична формула, не навчена).

### PyTorch

```python
import torch
import torch.nn as nn

class SelfAttention(nn.Module):
    def __init__(self, embed_dim):
        super().__init__()
        self.query = nn.Linear(embed_dim, embed_dim)
        self.key = nn.Linear(embed_dim, embed_dim)
        self.value = nn.Linear(embed_dim, embed_dim)
        self.embed_dim = embed_dim

    def forward(self, x):
        Q = self.query(x)   # (batch, seq_len, embed_dim)
        K = self.key(x)
        V = self.value(x)

        scores = Q @ K.transpose(-2, -1) / (self.embed_dim ** 0.5)  # (batch, seq_len, seq_len)
        weights = torch.softmax(scores, dim=-1)   # по рядку — вагам одного токена
        output = weights @ V                       # (batch, seq_len, embed_dim)

        return output
```

`Q`, `K`, `V` рахуються **паралельно** (три окремі `Linear`, не ланцюжок один за одним — на відміну від `conv1→conv2→fc` у CNN). `scores.shape = (batch, seq_len, seq_len)` — повна матриця релевантності кожен-до-кожного. Self-attention **зберігає форму входу**: `output.shape == x.shape`.

### Чому це паралельно, а не послідовно (як RNN)

Весь процес — **три матричні операції**, кожна рахується одразу для **всіх** токенів:

1. `scores = Q @ Kᵀ` — релевантність усіх пар одночасно, не пара за парою
2. `weights = softmax(scores)` — усі рядки одразу
3. `output = weights @ V` — знову вся матриця одразу

RNN змушений іти крок за кроком (токен 50 чекає результату токена 49). Attention обробляє всю послідовність одним проходом — саме тому Transformers тренуються набагато швидше на GPU (матричні операції — саме те, для чого GPU оптимізований).

### Positional encoding

Сам механізм attention (`Q·K`) **не бачить порядку** — переставиш токени, результат буде той самий, тільки переставлений. Тому до ембедингу кожного токена **додається** окремий, унікальний для його позиції вектор, ще до входу в attention:

```
x_with_position = token_embedding + position_encoding
```

(Оригінальна стаття Transformer генерує ці вектори через sin/cos хвилі різної частоти — деталі формули не критичні для розуміння ідеї.)

## Gotchas

- **`Q`, `K`, `V` — паралельні проекції одного `x`, не ланцюжок.** Написати `x=query(x); x=key(x); x=value(x)` — легка, природна помилка (переносить звичний CNN/MLP-патерн туди, де він не підходить). Правильно: три окремі змінні, усі від оригінального `x`.
- **`nn.Linear(embed_dim, embed_dim)` для всіх трьох** — `Linear` дивиться на **останній** вимір входу (`embed_dim`), не на `batch`/`seq_len`.
- **Dot product — скаляр (сума добутків), не вектор (поелементний добуток).** `[1,0]·[1,0] = 1*1+0*0 = 1`, не `[1,0]`.
- **Залежність Q/K/V — тільки при використанні, не при обчисленні.** Усі три рахуються незалежно й одночасно з `x`; `Q` і `K` використовуються разом лише на наступному кроці (rахунок `scores`).
- **`√d` у знаменнику — не для краси.** Без нього при великому `embed_dim` scores можуть вирости настільки, що softmax стає майже "жорстким" вибором (втрачає м'якість, важче тренувати).
