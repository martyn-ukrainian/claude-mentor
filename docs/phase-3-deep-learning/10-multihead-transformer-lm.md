# 10 — Multi-head attention, Transformer block і власна крихітна мовна модель

## Що це

**Multi-head attention** — це кілька self-attention "голів", що працюють паралельно: кожна зі своїми Q/K/V-проекціями і своєю матрицею scores, тобто своїм окремим "поглядом" на те, хто кому в послідовності релевантний. **Transformer block** — це attention, обгорнутий у residual connection, LayerNorm і FeedForward — стандартний "поверх", з яких складаються сучасні моделі (GPT-2 small — 12 таких поверхів). А зі стопки цих блоків + ембедингів ми зібрали **посимвольну мовну модель**, натреновану на цих самих конспектах.

## Для чого

Одна голова attention може виразити лише один патерн зв'язків між токенами. Але у реченні токени пов'язані по-різному одночасно: "спить" відноситься до "кіт" (хто?) інакше, ніж до "вчора" (коли?). Кілька голів = кілька незалежних патернів релевантності за ту саму ціну обчислень (голови ділять ембединг між собою, не копіюють його).

А мовна модель — це відповідь на питання "як з цих блоків виходить ChatGPT": у нас є текст як цифри, ми проганяємо через модель тисячі випадкових шматків, щоб вона надивилась, що зазвичай йде після якого контексту — і потім вона генерує текст по одному символу, враховуючи весь попередній контекст, у реальному часі. (Коли ChatGPT "друкує" відповідь поступово — це не анімація, це той самий цикл генерації.)

## Розбір

### Multi-head: подорож тензора

Вхід `(1, 3, 8)` — батч, 3 токени, 8 чисел на токен. 2 голови ділять 8 чисел навпіл: `head_dim = 8 / 2 = 4`.

```
(1, 3, 8)      # після Linear-проекції
(1, 3, 2, 4)   # view: розрізали 8 на 2 голови × 4
(1, 2, 3, 4)   # transpose(1, 2): перегрупували "по токенах" → "по головах"
```

Після цього кожна голова — матриця `(3 токени × 4 числа)`, тобто рівно вхід одноголового attention з Уроку 09, тільки менший. `@` рахує обидві голови одним викликом (PyTorch множить по двох останніх вимірах, все спереду вважає "стопкою"):

```python
scores = query @ key.transpose(-2, -1) / (self.head_dim ** 0.5)
weights = torch.softmax(scores, dim=-1)
output = (weights @ value).transpose(1, 2)                      # назад "по токенах"
output = output.reshape(batch, -1, self.num_heads * self.head_dim)  # склеїли голови
return self.R(output)   # фінальний Linear змішує "думки" голів
```

Ділимо на корінь з `head_dim` (не `embed_dim`) — бо dot products тепер між векторами по 4. Навіщо взагалі ділити: великі scores → майже жорсткий softmax → нульові градієнти для "програвших" токенів.

### Transformer block — патерн "Add & Norm"

```python
x = self.norm1(x + self.attention(x))
x = self.norm2(x + self.ffn(x))
```

- **Residual (`x + ...`)**: шар додає поправку, а не переписує токен з нуля; градієнт має пряму трасу повз шар — у глибоких мережах без цього він би не доповз до перших шарів (vanishing gradient, Уроки 02/08).
- **LayerNorm**: родич BatchNorm (Урок 07), але нормалізує вектор кожного токена окремо, не статистику батчу.
- **FFN**: `Linear(8→32) → ReLU → Linear(32→8)` через `nn.Sequential`. Attention збирає контекст МІЖ токенами, FFN потім обробляє кожен токен окремо.

### Causal mask — заборона списувати

Ціль тренування — наступний символ, а він фізично присутній у вхідному вікні праворуч. Без заборони модель навчиться копіювати сусіда (loss ~0, розуміння 0), а на генерації, де майбутнього не існує, буде безпорадна. Заборона вшивається в scores до softmax:

```python
T = scores.shape[-1]
mask = torch.tril(torch.ones(T, T))                    # нижній трикутник
scores = scores.masked_fill(mask == 0, float("-inf"))  # майбутнє → -inf → softmax дає рівно 0
```

Іронія: щойно вчили "softmax ніколи не дає рівно 0, щоб градієнт тік" — а тут навмисно робимо рівно 0, бо це структурна заборона, а не "токен здався неважливим".

### TinyLM — вся модель

```
індекси (16, 64)
  → token_emb: вектори символів (16, 64, 32)     # nn.Embedding = таблиця, що навчається
  + pos_emb(arange(64)): вектори позицій          # attention сам не бачить порядку
  → 2 × TransformerBlock                          # контекст між токенами
  → head: Linear(32 → 166)                        # 166 ставок "який символ наступний"
```

Дані: всі `docs/phase-3-deep-learning/*.md` як один рядок (57k символів), словник зі 166 унікальних символів, `stoi`/`itos` (dict comprehension + `enumerate`). Батч — 16 випадкових вікон по 64 символи, ціль = те саме вікно, зсунуте на +1 (кожна позиція = окреме завдання "вгадай наступний").

Тренування — звичний цикл (Adam `lr=1e-3`, `CrossEntropyLoss`), одна зморшка: loss хоче `(N, класи)` + `(N,)`, тому `logits.reshape(-1, vocab_size)` і `y.reshape(-1)` — валимо всі 16·64 передбачень в один список.

Генерація — автогресивний цикл: прогнати контекст → взяти logits **останньої** позиції `logits[0, -1]` → softmax → `torch.multinomial` (семплінг пропорційно ймовірностям, НЕ argmax — інакше модель зациклюється) → доклеїти через `torch.cat` → повторити. Кожен новий символ = повний прогін моделі: тренування паралельне по позиціях, генерація — принципово послідовна.

**Результат:** loss 5.31 → ~2.5. На 2000 кроках — напів-марення з українськими словоформами і markdown-артефактами; на 5000 — з'являються справжні слова з конспектів. Модель ніколи не бачила української — всі патерни витягла зі статистики символів.

## Gotchas

- **`view` після `transpose` падає** (`view size is not compatible... Use .reshape()`): transpose "переплутує" порядок у пам'яті, а view вимагає суцільності. Правило: після transpose — `reshape` (той самий view, але вміє скопіювати за потреби).
- **Два різні `-1`**: у `view(-1, ...)` це "порахуй цей вимір сам" (дозволений один на виклик); у номерах вимірів (`transpose(-2, -1)`, `dim=-1`) — "з кінця".
- **`{i, ch}` — це set, `{i: ch}` — dict.** Кома замість двокрапки у фігурних дужках мовчки створює множину; видає себе випадковим порядком елементів при друку.
- **Паралельні гілки — не конвеєр.** `pos_emb` їсть НОМЕРИ позицій (`torch.arange(T)`), і результат ДОДАЄТЬСЯ до token_emb — не `pos_emb(token_emb(x))`. Той самий клас помилки, що Q/K/V ланцюжком у Уроці 09.
- **Стартовий loss можна передбачити**: рівномірне вгадування з N класів дає `-log(1/N)`; для 166 символів ≈ 5.1. Якщо перший loss сильно інший — баг ще до навчання.
- **`randint` верхня межа exclusive** — тому `len(data) - BLOCK_SIZE` вже лишає місце для зсуву на +1, додатковий `-1` не потрібен.
- **Модуль з цифри на початку** (`10_multihead_attention.py`) не імпортується звичайним `import` — тільки `importlib.import_module("10_...")`. І при імпорті виконується весь файл — тести ховати під `if __name__ == "__main__":`.
- **Ваги бувають різні**: ваги моделі (у `nn.Linear`, навчаються, фіксовані після тренування) ≠ attention weights (рахуються заново для кожного входу; модель вчиться не їх, а вміння їх рахувати).
