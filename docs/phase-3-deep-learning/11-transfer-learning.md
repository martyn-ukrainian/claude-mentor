# 11 — Transfer learning: чужий "зір" для своєї задачі

## Що це

Навчання на основі вже існуючої натренованої моделі: береш чужі ваги (наприклад, ResNet18, натренований на 1.2 млн фото ImageNet) і донавчаєш тільки ту частину, яка потрібна під твою задачу. Важливо: заморожені шари **не видаляються** — всі 11.7M параметрів лишаються і працюють у кожному forward, вони просто **не вчаться** (градієнти по них не рахуються). Дешевшим стає тренування, не запуск. (Зменшення моделі "щоб влізла на слабше залізо" — це окремі техніки: pruning, квантизація, дистиляція.)

## Для чого

Ранні шари CNN вчать **універсальні** ознаки (краї → текстури → форми), і вони однаково корисні для котів, цифр чи теплиць. Тому на задачі, де своїх даних катастрофічно мало, з нуля тренуватись безнадійно — а з чужим "зором" виходить пристойно: у нас **78% на 500 картинках** котів/собак (найважча пара CIFAR-10), де тренування з нуля дало б ~55-60%, а монетка — 50%. Тренувалась при цьому крихітна частка моделі. В індустрії з нуля майже ніхто не тренує — fine-tuning готових моделей і є стандартний робочий режим (YOLO для дронів — той самий патерн).

## Розбір

### Feature extraction — заморозка + нова голова

```python
model = models.resnet18(weights="IMAGENET1K_V1")   # 11 689 512 параметрів

model.requires_grad_(False)          # заморозити ВСЕ (autograd їх більше не чіпає)
model.fc = nn.Linear(512, 2)         # нова голова: 2 класи замість чужих 1000
```

- `fc` у ResNet мав `Linear(512, 1000)` — по одній ставці на кожен клас ImageNet. Принцип "виходи останнього шару = кількість класів" — той самий, що 10 цифр у MNIST-CNN і 166 символів у TinyLM.
- Нова голова народжується з `requires_grad=True` → тренується **тільки вона**: 512×2+2 = **1 026 параметрів з 11.7 мільйонів (0.009%)**.
- Модель "схудла" з 11 689 512 до 11 177 538 — рівно на стару голову (513 000 → 1 026).

### Дані: чужа нормалізація — закон

```python
transform = transforms.Compose([
    transforms.Resize(224),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
])
```

Ці mean/std — **статистика ImageNet**, порахована один раз по тренувальному набору. Це StandardScaler-принцип з Фази 2: нормалізація належить тренуванню — навіть чужому. Свої числа підставляти не можна: заморожені ваги "звикли" до цього масштабу входу.

Вибірка: CIFAR-10 (50 000 картинок, 10 класів) → фільтр міток кіт(3)/собака(5) comprehension-ом по `dataset.targets` → `Subset(dataset, indices)` — "плейліст" над датасетом, який нічого не копіює. Мітки перемапити в 0/1 прямо в циклі: `(y == 5).long()` — бо `CrossEntropyLoss` чекає класи `0..1`, а не 3 і 5.

### Повний конвеєр (11b): val split → early stopping → чекпойнт

```python
train_part, val_part = random_split(train_subset, [400, 100])   # val — З TRAIN, не з test!

for epoch in range(N_EPOCH):
    ...тренування по train_part...
    ...val loss по val_part (no_grad)...
    if avg_val_loss < best_val_loss:
        best_val_loss = avg_val_loss
        patience_counter = 0
        torch.save(model.state_dict(), "best_model.pt")   # чекпойнт найкращого стану
    else:
        patience_counter += 1
    if patience_counter >= 2:
        break                                             # early stopping

model.load_state_dict(torch.load("best_model.pt"))        # повернутись до best
model.eval()
...оцінка на test...
```

Реальний запуск: val падав до епохи 7 (0.515), епохи 8-9 — погіршення → early stopping; test міряли **найкращою** версією, не останньою → **78.0%** проти 75.5% без конвеєра.

### lr для нових vs претренованих ваг (емпірично перевірено)

Експеримент: lr голови 1e-3 → 1e-4 упустив accuracy 75.5→65% — свіжа випадкова голова просто не встигла навчитись. Правило: **новим випадковим вагам — сміливий lr (1e-3), чужим претренованим (якщо розморожуєш layer4) — обережний (1e-4)**, щоб не зруйнувати викопане. Механізм для різних lr в одній моделі — param groups:

```python
optimizer = torch.optim.Adam([
    {"params": model.fc.parameters(), "lr": 1e-3},
    {"params": model.layer4.parameters(), "lr": 1e-4},
])
```

## Gotchas

- **Заморожені ≠ видалені.** Forward іде крізь усі шари завжди; заморозка економить тільки backward/оптимізатор. Плутати з pruning/дистиляцією (ті справді зменшують модель).
- **Навіщо заморозка по суті:** 500 прикладів проти 11.7M параметрів = миттєвий overfitting, а градієнти від малих даних зруйнували б універсальні фічі. Заморозка захищає чуже знання від своїх маленьких даних.
- **Індекси не переносяться між наборами.** Фільтр, порахований по `train_data.targets`, не можна застосовувати до `test_data` — під тими самими індексами інші картинки. Кожному набору — свій фільтр.
- **Val ріжеться з train, не з test.** Вибір найкращої епохи по test = leakage, оцінка завищена (та сама пастка, що в Уроці 07).
- **random_split спершу, DataLoader потім.** Якщо train_loader збудований на повному subset-і, модель тренується на val-прикладах — val loss бреше.
- **Early stopping без чекпойнта лишає погіршену модель:** зупинка з patience=2 означає, що в пам'яті версія, яка вже 2 епохи як гірша. `torch.save` best-стану + `load_state_dict` перед тестом — обов'язкова пара.
- **`random_split` хоче цілі довжини** — `//`, не `/` (float впаде).
- **`метод_()` з підкресленням = in-place** (PyTorch-конвенція): `requires_grad_(False)` змінює модель на місці.
- **`.pt` файли — у `.gitignore`** (блок models з Фази 0 нарешті працює на реальному чекпойнті).
