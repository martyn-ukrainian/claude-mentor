# 13 — Карта ML: яку модель коли (5 питань до будь-якої задачі)

## Що це

Не список моделей, а **порядок питань**, які ставиш до будь-якої нової задачі — і відповіді на них самі вказують на клітинку з інструментом. Кожна модель курсу (від `LogisticRegression` до `nn.LSTM`) — одна клітинка на цій карті.

## Для чого

Після Фази 3 інструментів багато, а відчуття "куди який" — немає: перед сирою базою даних (наприклад, вакансії з DOU) незрозуміло, з якого боку підійти. Це нормальний стан після марафону "інструмент за інструментом" — бракує не знань, а рамки. П'ять питань нижче і є ця рамка: пройшов їх по черзі — знаєш, з чого починати.

## Розбір — п'ять питань

### 1. Є мітки `y`? (правильні відповіді для прикладів)
- **Так** → **supervised** — навчання на парах "вхід → відповідь": churn у Telco, цифри MNIST, коти/собаки, вердикт по вакансії
- **Ні** → **unsupervised** — шукаємо структуру в самих даних: K-Means (групи клієнтів без міток), PCA

Пастка: "мітка" — це не будь-яке поле (локація — не мітка), а саме те, що хочемо передбачати.

### 2. Відповідь — число чи категорія?
- **Число будь-якого значення** (ціна, температура, return) → **регресія**: `LinearRegression`, GB-регресор, мережа з `Linear(…, 1)`, LSTM з лінійним виходом
- **Категорія зі списку** (спам/ні, кіт/пес, ПОДАВАТИ/НЕ ПОДАВАТИ) → **класифікація**: логістична регресія, RF/GB, KNN/SVM/NB, CNN, будь-яка мережа з `Linear(…, n_класів)` + cross-entropy

Одна й та сама архітектура буває і тим, і тим — різниця в останньому шарі й loss. І число "0.8" чи "8 з 10" на виході класифікатора — це **впевненість** (`predict_proba`), задача від цього регресією не стає.

### 3. Якої форми дані? ← найчастіша дірка
- **Таблиця** (рядки × стовпці) → **класика перша**: логістична/RF/GB — швидше, точніше на малих даних, пояснювано. Нейромережі тут майже завжди програють.
- **Текст** → спершу текст → числа (найпростіше TF-IDF: які слова і як часто), далі знову класика; трансформери — якщо класика впирається
- **Картинки** → CNN / transfer learning
- **Послідовності / час** → LSTM/Transformer, або класика на ознаках, порахованих із вікна

Тонкість на прикладі DOU: дані **табличні за формою** (є колонки), але **головний сигнал — текстовий** (в описі вакансії сидить те, чого нема в полях: вимоги до освіти, English, стек). Дивитись треба не на те, як зберігається, а де сидить зміст.

### 4. Скільки даних?
- **Сотні – тисячі** → класика (нейромережа з нуля зазубрить і не узагальнить)
- **Десятки тисяч +** → можна DL з нуля
- **Мало, але є претренована модель для схожої задачі** → transfer learning (500 картинок → 78%)

2000 класифікованих вакансій — нормально для класики, мало для DL з нуля.

**Окрема пастка — дисбаланс класів.** DOU: 90% "НЕ ПОДАВАТИ", 5% "ПОДАВАТИ", 5% "УТОЧНИТИ". Модель "завжди НІ" матиме 90% accuracy і нуль користі — вона пропустить кожен хороший офер. Судити треба по recall/precision/F1 **на рідкому класі**, як на Telco (Урок 04 Фази 2).

### 5. Бейзлайн? (завжди, для будь-якої моделі)
Найтупіша модель першою — інакше нема з чим порівнювати:
- регресія → "передбач середнє" або "завтра = сьогодні" (LSTM на BTC цей бейзлайн програла — і це був правильний результат)
- класифікація → majority class ("завжди НЕ ПОДАВАТИ")

Розумна модель має бути краща за бейзлайн **за правильною метрикою** — інакше вона нічого не дає.

## Приклад: DOU-вакансії за п'ять кроків
мітки є (вердикт Haiku) → класифікація (3 класи) → табличне за формою, текст усередині → 2000 прикладів = класика → бейзлайн majority, метрика recall/F1 на "ПОДАВАТИ". План коду: TF-IDF + логістична регресія, потім GB, потім (якщо впреться) трансформер.

## Gotchas
- **Класика ≠ "гірша за нейромережі"** — на таблицях і малих даних вона зазвичай краща. Спочатку бейзлайн, потім класика, потім DL — не навпаки.
- **Форма зберігання ≠ форма сигналу**: CSV з текстовою колонкою — це текстова задача.
- **Accuracy на дисбалансі бреше** — рідкий клас, а не загальний відсоток.
- **Розмір даних вирішує "чи можна DL"** — не бажання спробувати трансформер.
