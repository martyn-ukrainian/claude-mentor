# 04b — sklearn vs PyTorch: коли який інструмент і звідки в моделі «сенс»

*Концептуальний урок без коду — підсумок розмови «навіщо була Фаза 2, якщо у Фазі 3 є PyTorch».*

## Що це

Розбір місця двох головних інструментів курсу: **scikit-learn** (класичний ML, Фаза 2) і **PyTorch** (deep learning, Фаза 3) — чому це не «стара і нова версія», а два сусідні інструменти для різних класів задач. Плюс два супутні поняття: як формулюється таргет для бізнес-задачі передбачення і звідки в нейромережі береться «сенс».

## Для чого

Щоб не сприймати роадмап як драбину, де кожна фаза замінює попередню. sklearn — індустріальний стандарт для табличних задач (відтік клієнтів, «кому запропонувати продукт», кредитний скоринг) — це величезна частка комерційного ML. PyTorch відкриває інший клас задач — сирі дані (картинки, текст, аудіо). ML-інженера відрізняє вміння **вибрати** інструмент під задачу і обґрунтувати вибір.

## Розбір

### 1. Коли класика (sklearn), а коли нейромережа (PyTorch)

- **sklearn** — швидкий спосіб працювати з наявними табличними даними: кому дати знижку, хто піде (churn), хто купить (propensity), обрати найкращого кандидата. Готові перевірені моделі «з коробки».
- **PyTorch** — конструктор для власних моделей, працює з набагато більшими і частіше нетабличними даними: картинки, текст, аудіо.
- **Ключова різниця — НЕ «хто вчиться сам».** Обидва вчаться самі: `fit()` у sklearn так само підбирає ваги, мінімізуючи loss (часто тим самим градієнтним спуском, який ми писали руками). Справжня різниця — **хто робить X**: у класиці ознаки конструює людина (tenure, тариф, витрати), у deep learning мережа сама витягує ознаки з сирих даних (пікселі → краї → форми → «вуха» → кіт). Це називається *representation learning*.
- **Принцип «спочатку бейзлайн»:** спершу проста sklearn-модель; нейромережу беремо тільки якщо бейзлайн не тягне. У табличних задачах класика часто б'є нейромережі: швидше, дешевше, легше пояснити бізнесу.
- sklearn не зникає у torch-проєктах: `train_test_split`, метрики, крос-валідація, препроцесинг — все одно з нього.

### 2. Таргет для бізнес-задачі: «кому продати новий тариф»

Достатньо звичайного sklearn. Але треба розрізняти **три шари**, які легко сплутати:

1. **Таргет (y)** — `купив тариф / не купив`. Факт, що вже стався, як `Churn Yes/No` у Фазі 2.
2. **Фільтр рядків** — вчимось тільки на тих, **кому пропонували** (для нового продукту — пілотна кампанія). Якщо взяти просто «хто має тариф» по всій базі, змішаємо тих, хто відмовився, з тими, кому ніхто не пропонував — а це різні люди.
3. **Бізнес-пріоритезація** — поверх `predict_proba`: з двох клієнтів з однаковою ймовірністю дзвонимо спершу прибутковішому. Це рішення бізнес-логіки, не моделі.

Схема цілком: пілот → навчання на учасниках пілоту (y = підключив чи ні) → `predict_proba` на всіх інших → сортуємо → топ отримує пропозицію.

### 3. Звідки в нейрона береться «сенс»

Свіжий нейрон з випадковими вагами не означає нічого — і ніхто сенс у нього не вписує. **Сенс заповнюється під тиском градієнта і мінімізації loss у процесі навчання:** нейрону «вигідно» стати чутливим до ознаки (напр., гострих вух у класифікаторі котів), бо це зменшує помилку — градієнти виліплюють з порожнього нейрона детектор ознаки. Сенс — це роль, набута в розподілі праці, а не закладена властивість.

Причому сенс зазвичай **розмазаний** по багатьох нейронах — поняття кодується візерунком активацій. Звідси embeddings: схожі за сенсом речі опиняються поруч у просторі (класика: вектор(король) − вектор(чоловік) + вектор(жінка) ≈ вектор(королева)). Без Y немає тиску — без тиску немає сенсу: саме ціль визначає, який сенс мережа витягне з X.

## Gotchas

- **«Модель сама вчиться» ≠ різниця між класикою і DL.** Обидві вчаться самі. Різниця в тому, хто робить фічі. (Цей misconception сплив у мене двічі за сесію — маркер для повторення.)
- **«Хто має тариф» — не таргет.** Без фільтра «серед тих, кому пропонували» модель вчиться на змішаній вибірці.
- **Розрив «фаза N замінює фазу N−1»** — хибна модель. Концепції (loss, градієнт, overfitting, метрики, data leakage) — наскрізні; бібліотеки — паралельні інструменти.
- Твердження моделі-ментора (і будь-якої LLM) — статистичний зліпок з навчальних даних, не звірена база. Перевіряти, особливо конкретику про API.
