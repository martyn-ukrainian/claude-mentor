# 02 — ReLU + backprop для мережі з двох шарів

## Що це

Дві речі. По-перше — **ReLU**, ще одна функція активації, простіша за sigmoid:

```
relu(z) = max(0, z)
```

Якщо `z` додатнє — пропускаємо як є, якщо від'ємне — обнуляємо.

По-друге — **backpropagation для мережі з кількох шарів**, а не одного нейрона (Урок 01). Це те саме chain rule, тільки ланцюжок довший, бо градієнт має "пройти" через два шари, а не один.

## Для чого

**ReLU.** У Уроці 01 ми рахували градієнт через похідну sigmoid, `a(1-a)`. Проблема: на краях sigmoid (де `z` дуже велике або дуже від'ємне) крива майже плоска — похідна там близька до нуля, максимум `0.25` навіть у найкращій точці. Якщо мережа глибока (багато шарів), кожен шар при backprop множить градієнт ще на одне маленьке число — градієнт "згасає" (**vanishing gradient**), і глибокі шари фактично перестають вчитись.

ReLU рятує від цього: для активних нейронів (`z>0`) похідна рівно `1` — множення на `1` нічого не "з'їдає". Тому ReLU — стандартний вибір активації для hidden-шарів у сучасних мережах (sigmoid лишається переважно для output-шару в задачах класифікації).

**Backprop через кілька шарів.** Реальні мережі мають не один нейрон, а стек шарів. Щоб натренувати всю мережу (не тільки останній шар), градієнт треба "пропустити" назад через усі шари до самого входу — це і є суть backpropagation.

## Розбір

### ReLU і її похідна

```python
def relu(z: np.ndarray) -> np.ndarray:
    return np.maximum(0, z)

def relu_derivative(z: np.ndarray) -> np.ndarray:
    return (z > 0).astype(int)
```

Перевірка на числах: `z = [-2, -1, 0, 1, 2]` → `relu(z) = [0, 0, 0, 1, 2]`, `relu_derivative(z) = [0, 0, 0, 1, 1]`.

Похідна: при `z>0` — `1` (пряма лінія з нахилом 1, `relu(z)=z`); при `z<0` — `0` (`relu(z)` завжди нуль, скільки `z` не крути); в `z=0` — формально злам, на практиці беруть `0` або `1`, не критично.

### Forward pass для мережі з двох шарів

Той самий принцип з Уроку 01 — вихід одного шару стає входом наступного:

```python
z1 = w1 * x + b1
a1 = sigmoid(z1)        # hidden-шар

z2 = w2 * a1 + b2
a2 = sigmoid(z2)         # output-шар

L = (a2 - y) ** 2
```

### Backprop: чому недостатньо формули з Уроку 01

У Уроці 01 ланцюжок був коротким: `w → z → a → L`. Тепер, для ваги `w1` у hidden-шарі, ланцюжок довший:

```
w1 → z1 → a1 → z2 → a2 → L
```

Права частина (`a2 → L`, тобто `dL/dz2`) — та сама формула, що й у Уроці 01, нічого нового. Нове — ланка `a1 → z2`, бо `z2 = w2*a1 + b2`: тут `a1` впливає на `z2` через множник `w2`. Тобто `dz2/da1 = w2`.

Повний ланцюжок множників для `dL/dz1`:

```
dL/dz1 = dL/dz2 · dz2/da1 · da1/dz1
       = [2(a2-y)·a2·(1-a2)] · w2 · [a1·(1-a1)]
```

**Чому саме множимо на `w2`.** Уяви крайній випадок `w2=0`: тоді `z2 = 0*a1 + b2 = b2` — `a1` взагалі не впливає на `z2`, а отже й на `L`. Скільки б `w1` не міняли (а значить і `a1`) — `loss` не поворухнеться, тому й немає сенсу сильно оновлювати `w1`. Навпаки, при великому `w2` — найменша зміна `a1` сильно "трясе" `z2`. Тобто `w2` буквально вимірює, наскільки сильно шлях від `a1` до `L` підсилений чи послаблений — і градієнт для `w1` має бути пропорційний цій силі впливу. Це і є суть backpropagation: помилка (error signal) біжить назад від output до hidden, масштабуючись вагами того шляху, яким вона йде.

Далі — звичайний chain rule, як у Уроці 01:

```
dL/dw1 = dL/dz1 * x     (бо z1 = w1*x + b1)
dL/db1 = dL/dz1 * 1
dL/dw2 = dL/dz2 * a1    (бо z2 = w2*a1 + b2)
dL/db2 = dL/dz2 * 1
```

### Код градієнтного спуску для мережі з двох шарів

```python
def mlp_gradient_descent(x, y, lr=0.1):
    w1, b1, w2, b2 = 0.0, 0.0, 0.0, 0.0

    for i in range(50):
        z1 = w1 * x + b1
        a1 = sigmoid(z1)
        z2 = w2 * a1 + b2
        a2 = sigmoid(z2)

        dL_dz2 = 2 * (a2 - y) * a2 * (1 - a2)
        dL_dz1 = dL_dz2 * w2 * a1 * (1 - a1)

        dL_dw2 = dL_dz2 * a1
        dL_db2 = dL_dz2 * 1
        dL_dw1 = dL_dz1 * x
        dL_db1 = dL_dz1 * 1

        w2 -= lr * dL_dw2
        b2 -= lr * dL_db2
        w1 -= lr * dL_dw1
        b1 -= lr * dL_db1
```

Результат: `loss` спадає з `0.25` до `0.082` за 40 ітерацій — обидва шари вчаться одночасно, кожен зі своєю частиною градієнта.

## Gotchas

- **`dL/dz1` вимагає множення на вагу наступного шару (`w2`), не тільки на локальну похідну активації.** Це і відрізняє backprop для мережі від backprop для одного нейрона — градієнт "переносить" інформацію про те, наскільки сильно даний нейрон впливає на кінцевий результат через усі шари, що йдуть після нього.
- **Не плутати `relu(z)` з `relu_derivative(z)`.** `relu(z) = max(0, z)` повертає саме значення `z` (або 0), а не бінарний прапорець. Легко випадково написати `(z>0).astype(int)` для самої `relu` — це вихід, що виглядає правильно на позитивних `z`, але завжди дає `1`, а не саме число `z`.
- **Похідна ReLU: знак порівняння легко переплутати.** Треба `1` там де `z>0`, `0` де `z≤0` — не навпаки.
- **Forward pass ≠ backward pass.** Forward — просто рахуємо прогноз (`x → z1 → a1 → z2 → a2`), жодних градієнтів. Backward — рахуємо, як змінити ваги, рухаючись від `L` назад до входу. Легко сплутати, коли думаєш про "прохід через мережу" загалом.
- **Vanishing gradient — не абстрактна проблема, а причина чому ReLU став дефолтом.** Sigmoid у глибоких мережах (багато шарів підряд) практично зупиняє навчання ранніх шарів, бо похідна `≤0.25` на кожному шарі перемножується сама на себе.
