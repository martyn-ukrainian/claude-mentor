# 08 — RNN/LSTM: основи роботи з послідовностями

## Що це

**RNN (Recurrent Neural Network)** — архітектура для послідовних даних (текст, часові ряди, аудіо), де порядок елементів має значення, а довжина входу не фіксована. На відміну від `CNN` (Урок 05, фіксоване локальне вікно) чи `Linear` (фіксований розмір входу цілком), RNN обробляє послідовність **по одному елементу за раз**, підтримуючи "пам'ять" (**hidden state**) — вектор, який передається з кроку на крок і накопичує інформацію про все, що вже було "прочитано".

**LSTM (Long Short-Term Memory)** — розвиток RNN з додатковим механізмом "воріт" (gates), що вирішує конкретну проблему простого RNN — забування інформації на довгих послідовностях.

## Для чого

CNN добре підходить для картинок, бо там працює **локальність** — сусідні пікселі пов'язані, далекі здебільшого ні. У тексті це не так: значення слова може залежати від контексту **далеко** в реченні ("кіт, який щойно з'їв всю рибу, **втомлено** ліг спати" — "втомлено" стосується "кота", а між ними купа інших слів). Фіксоване локальне вікно (kernel) це не вловить — потрібен механізм, що несе інформацію через **всю** послідовність, а не тільки сусідні елементи.

## Розбір

### Механіка RNN

Один крок: `h_нове = f(h_старе, x_поточний)` — нове приховане значення залежить і від попередньої пам'яті, і від поточного входу.

```python
rnn = torch.nn.RNN(input_size=1, hidden_size=4, batch_first=True)
x = torch.randn(1, 5, 1)  # (batch, seq_len, input_size)
output, hidden = rnn(x)
# output.shape → (1, 5, 4) — hidden state на КОЖНОМУ з 5 кроків
# hidden.shape → (1, 1, 4) — тільки ОСТАННІЙ hidden state (підсумок всієї послідовності)
```

`nn.RNN` — це шар, як `nn.Conv2d`/`nn.Linear`: використовується як **атрибут** усередині власного `nn.Module`, не як батьківський клас для наслідування.

### Практика: RNN, що вчиться рахувати суму послідовності

```python
class RNNSum(torch.nn.Module):
    def __init__(self, hidden_size=16):
        super().__init__()
        self.rnn = torch.nn.RNN(input_size=1, hidden_size=hidden_size, batch_first=True)
        self.linear = torch.nn.Linear(hidden_size, 1)

    def forward(self, x):
        output, hidden = self.rnn(x)
        x = self.linear(hidden.squeeze(0))  # прибрати вимір "кількість шарів RNN"
        return x
```

Дані — 1000 випадкових послідовностей довжиною 5 (`torch.randint(0, 10, (1000, 5))`, потім `.unsqueeze(-1)` для форми `(1000, 5, 1)`), мітка `y = X.sum(dim=1)` — сума по осі `seq_len` (**не** `dim=0`, це підсумок по батчу — легко переплутати, дає геть інший, неправильний масштаб цілі).

Loss — `nn.MSELoss()` (передбачаємо число, не клас — той самий вибір, що в Уроці 03, перше знайомство з PyTorch).

**Результат:** після тренування на 1000 прикладах, на новому тестовому `[1,2,3,4,5]` (справжня сума `15`) модель видала передбачення **≈15** — узагальнила задачу підсумовування на приклад, якого не бачила.

### LSTM

```python
lstm = torch.nn.LSTM(input_size=1, hidden_size=4, batch_first=True)
output, (hidden, cell) = lstm(x)  # ДВА стани пам'яті: hidden + cell
```

**Проблема, яку вирішує LSTM:** на довгих послідовностях градієнт при `backward()` проходить через усі часові кроки назад, і на кожному кроці множиться ще раз (chain rule). Якщо ці множники стабільно менші за 1 — градієнт затухає до нуля задовго до початку послідовності (**vanishing gradient**, той самий механізм, що й у глибоких мережах через шари, Урок 02 — тільки тут "глибина" по часу, не по шарах).

LSTM додає gates — окремі навчені механізми, що вирішують що **пам'ятати**, що **забувати**, і що **пропустити на вихід** на кожному кроці, замість сліпого перезапису hidden state. API майже ідентичний `nn.RNN` — практична заміна: `self.rnn = torch.nn.LSTM(...)`, і `forward` розпаковує `output, (hidden, cell) = self.rnn(x)`.

**На короткій послідовності (5 кроків) різниці між RNN і LSTM майже не побачити** — vanishing gradient стає реальною проблемою тільки на довгих послідовностях (сотні кроків). Тому в цьому уроці LSTM показаний концептуально й через shape-demo, без окремого повного проекту.

## Gotchas

- **`nn.RNN`/`nn.LSTM` — шари, використовуються як атрибут (`self.rnn = nn.RNN(...)`), не як батьківський клас.** `class MyModel(nn.RNN)` — неправильно, той самий принцип, що з `nn.Conv2d`/`nn.Linear`.
- **`self.rnn(x)` повертає кортеж, не одне значення.** Обов'язково розпакувати: `output, hidden = self.rnn(x)` (для RNN), `output, (hidden, cell) = self.rnn(x)` (для LSTM).
- **`.squeeze()` без аргументу — ризиковано.** Прибирає **всі** виміри розміром 1, не тільки потрібний. `.squeeze(0)` — явно вказати, який вимір прибрати.
- **`dim` при `.sum(dim=N)` на 3D-тензорі `(batch, seq_len, input_size)`** — `dim=0` підсумовує по батчу (неправильно для мітки "сума однієї послідовності"), `dim=1` підсумовує по кроках послідовності всередині кожного прикладу (правильно тут). Легко переплутати, наслідок — астрономічно неправильний масштаб цілі і loss.
- **Тренування на тестовому прикладі ≠ оцінка.** Виклик тренувального циклу (`backward`/`step`) на тестових даних не перевіряє узагальнення — модель просто завчить цю одну відповідь. Оцінка — чистий `forward`, без градієнтних кроків (той самий принцип train vs eval, що в Уроці 07).
