# Урок 09 — Feature Engineering, GridSearchCV, PCA, K-Means

## Що це

Три різні інструменти, об'єднані одним питанням: **у нас забагато варіантів, щоб перебирати руками — хто/що робить це автоматично?**

- **`GridSearchCV`** — автоматично перебирає сітку гіперпараметрів, з крос-валідацією вбудованою одразу.
- **PCA (Principal Component Analysis)** — стискає скорельовані числові фічі в менше число нових, зберігаючи майже всю реальну інформацію.
- **K-Means** — групує схожі об'єкти без жодної відповіді (`y`) взагалі — unsupervised learning.

**Ключова відмінність між ними:** `GridSearchCV` — supervised (працює з `y`). `PCA` і `K-Means` — unsupervised (`y` не бачать під час навчання).

## Для чого

Це останній урок Фази 2 — «полірування» пайплайну перед тим, як зібрати все в capstone. `GridSearchCV` замінює ручний перебір (Урок 08). `PCA` вирішує мультиколінеарність (пастка, яку бачили в `feature_importances_`, Уроки 05-06). `K-Means` — перший unsupervised алгоритм курсу, показує, що структуру можна знайти навіть без цільової змінної.

### GridSearchCV — автоматизація ручного tuning

У Уроці 08 ти вручну перевіряв `C=100, 1, 0.01` і рахував CV окремо для кожного. `GridSearchCV` робить це одним викликом:

```python
from sklearn.model_selection import GridSearchCV

param_grid = {"model__C": [0.01, 0.1, 1, 10, 100]}

grid = GridSearchCV(pipe, param_grid, cv=5, scoring="accuracy")
grid.fit(X_train, y_train)

grid.best_params_   # {'model__C': 0.1}
grid.best_score_    # CV score на найкращому C
grid.score(X_test, y_test)  # чесна фінальна перевірка на test
```

**`"model__C"` — подвійне підкреслення** — спеціальний синтаксис Pipeline: «дістань крок з ім'ям `model`, постав туди параметр `C`». Без нього sklearn не знав би, до якого саме кроку застосувати значення.

**Результат обраного `C=0.1` узгоджується з висновком Уроку 08:** сусідні значення (`C=1`, `C=100`) там виявились статистично невідрізнимі за CV (різниця mean << std) — тому який саме з них «переможе» в `GridSearchCV` багато в чому залежить від шуму конкретного розбиття на фолди, не від принципової переваги.

### PCA — навіщо scaling (перевірено на реальних числах)

```python
df[numeric_cols].var()
# SeniorCitizen         0.14
# tenure               602
# MonthlyCharges        905
# TotalCharges    5 138 252
```

`TotalCharges` має variance у **мільйони разів** більшу за `SeniorCitizen` — просто через одиниці виміру (гривні проти 0/1), не через реальну важливість. PCA шукає напрямки **максимальної варіації** — без scaling він просто вказав би на `TotalCharges`, ігноруючи решту. Той самий механізм, що scaling для KNN/SVM (Урок 07): будь-який алгоритм, що рахує щось на основі variance/відстані, страждає без вирівнювання масштабів.

```python
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

X_numeric_scaled = StandardScaler().fit_transform(X_train[numeric_cols])
pca = PCA(n_components=2).fit(X_numeric_scaled)
pca.explained_variance_ratio_  # [0.552, 0.263] → разом 81.6%
```

### PCA — що фізично означає eigenvalue (три контрастні приклади)

Триптих реальних пар фіч із різною кореляцією:

| пара | кореляція | форма хмари точок | PC1 / PC2 split |
|---|---|---|---|
| tenure vs MonthlyCharges | r=0.25 (слабка) | майже кругла | 58% / 42% |
| MonthlyCharges vs TotalCharges | r=0.65 (помірна) | помітно витягнута | 81% / 19% |
| tenure vs TotalCharges | r=0.83 (сильна) | тонка «сигара» | 90% / 10% |

**Чим сильніша кореляція між двома фічами → тим тонша й витягнутіша хмара точок → тим більше PC1 забирає собі → тим дешевше викинути PC2.**

Механізм: `λ` (eigenvalue) вимірює, **наскільки сильно точки розкидані вздовж конкретного напрямку**. Великий `λ` = точки сильно відрізняються одна від одної в цьому напрямку = там реальна інформація, яку варто зберегти. Малий `λ` = точки вздовж цього напрямку майже однакові = можна відкинути, майже нічого не втративши.

**Практичний сенс:** якщо знаєш тільки значення точки вздовж PC1 (одне число замість двох), і хочеш вгадати, де вона приблизно перебуває («зверху справа» чи «знизу зліва») — вгадаєш майже завжди правильно, бо саме там живе 90% реальної різниці між точками. PC2 додає дуже мало нової інформації про те, «хто є хто».

**Контраст, щоб закріпити:** якби фічі були зовсім не скорельовані, хмара була б круглою — `λ` для PC1 і PC2 були б приблизно рівні, і не існувало б «зайвого» напрямку, який можна безкоштовно викинути.

### K-Means — unsupervised групування, що випадково знайшло реальний ризик

```python
from sklearn.cluster import KMeans

labels = KMeans(n_clusters=3, random_state=42).fit_predict(X_numeric_scaled)
```

Модель **ніколи не бачила** `Churn`. Але коли після навчання перевірили churn rate у кожній групі (той самий трюк з Фази 0: `.mean()` на бінарній колонці = частка):

| кластер | tenure | MonthlyCharges | TotalCharges | churn rate |
|---|---|---|---|---|
| 0 | 25.9 міс | $32.3 | $786 | 20% |
| 1 | 59.1 міс | $89.7 | $5301 | 20% |
| **2** | **14.4 міс** | **$80.1** | $1179 | **51%** |

Кластер 2 — «нові клієнти, які платять дорого» — churn **втричі** вищий за решту. K-Means не «знав» про churn — він просто згрупував схожих клієнтів за трьома числами. Але оскільки в реальності «новий+дорогий клієнт» дійсно частіше йде (це саме ті фічі, що мали найвищу `feature_importances_` в Уроці 05), геометрична група автоматично виявилась групою високого ризику.

## Gotchas

- **`GridSearchCV` не потребує окремого `pipe.fit()` перед собою** — `GridSearchCV.fit()` сам клонує пайплайн для кожної комбінації параметрів і кожного CV-фолду. Зайвий `pipe.fit()` до нього — даремна робота, результат ніде не використовується.
- **PCA не можна «витягнути» з уже навченого supervised `Pipeline`/`GridSearchCV`.** Той `ColumnTransformer` препроцесить числові **і** категоріальні фічі разом (десятки OneHot-колонок) — PCA на такому міксі розмиє сигнал. Для чистого дослідження мультиколінеарності серед числових фіч — окремий, простий `StandardScaler().fit_transform(X[numeric_cols])`, без повного `ColumnTransformer`.
- **PCA — не про ймовірність прогнозу.** Легко переплутати зі `predict_proba()` (Урок 03) — PCA взагалі не робить прогнозів, це препроцесинг/стиснення фіч.
- **K-Means дає групи, не причини.** Кластер із високим churn rate показує **де** шукати, не **чому** — інтерпретація («новий+дорогий клієнт») робиться людиною, дивлячись на профіль кластера після навчання.
- **`groupby(labels)` з pandas Series потребує `.values`**, якщо `labels` — звичайний NumPy масив без індексу (`pd.Series(y_train.values).groupby(labels).mean()`), інакше `groupby` намагатиметься зіставити мітки індексів, а не позиції.
